# Configuration

> **Шаблон.** Документ отвечает на вопрос «чем настраивается приложение и откуда
> берётся каждое значение». Единственный источник истины по списку переменных — схема
> валидации конфигурации в коде; документ объясняет смысл, а не дублирует схему
> механически. Значения секретов здесь не пишутся никогда.

## Способы конфигурации

Таблица: что задаётся, где, как попадает в код.

| Что | Где задаётся | Как попадает в код |
|---|---|---|
| **Подключения** (БД, хранилище, очереди) | конфиг платформы / строки подключения | ... |
| **Переменные** (не секреты) | закоммиченный конфиг | ... |
| **Секреты** | хранилище секретов платформы; локально — git-ignored файл | ... |

Как конфигурация валидируется: схема, тип `AppConfig`, **fail-fast** (неполная или
невалидная конфигурация не даёт приложению работать с половиной настроек, причина — в
логе), кешируется ли неудачная сборка. Как отказ проявляется на платформе (процесс не
стартует или каждый запрос получает `CONFIGURATION_ERROR`) — в
[Platform.md](Platform.md), «Ошибка конфигурации».

## Окружения

По пункту на окружение (production, dev, staging, тесты): чем отличается, какие ресурсы
у него свои, какие настройки заменены заглушками (почта в консоль, лимитер выключен).
Неочевидные причины выбора («почему локально так, а не иначе») — здесь же, абзацем.
Как тесты защищены от конфигурации разработчика — ссылкой на [Test-Setup.md](Test-Setup.md).

## Локальные файлы

Какие файлы конфигурации лежат в репозитории (пример с пустыми значениями —
закоммичен), какие только локально (git-ignored), как из примера получить рабочий
файл и какие значения в нём допустимы для локальной работы.

## Переменные

По подразделу на область (приложение, хранилище, аутентификация, платежи, …), в
заголовке — ссылка на ADR, которое задаёт правила области. Таблица:

| Переменная | Секрет | По умолчанию | Что |
|---|---|---|---|

Для лимитов и порогов — откуда взято значение и что сломается при его изменении.
Имена общих ресурсов — без префикса фичи; префикс — только у настроек одной фичи
(`DATABASE_URL`, а не `ORDERS_DATABASE_URL`, если база общая; `ORDERS_MAX_ITEMS` —
настройка одной фичи).
