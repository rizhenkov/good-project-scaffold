# API — документация

Документы, нужные только api. Общие для всех приложений (ADR, глоссарий, бэклог) — в
корневой [`docs/`](../../../docs/). Документы с пометкой «Шаблон» описывают, что в них
должно быть, и заполняются под проект.

## Оглавление

- [Architecture](Architecture.md) — шаблон: слои и структура `src/`, граница платформы, путь запроса, подсистемы, очереди и расписания.
- [Configuration](Configuration.md) — шаблон: способы конфигурации, окружения, локальные файлы, переменные.
- [DI Container](DI-Container.md) — ручная сборка зависимостей в `createContainer`, порты и `overrides` в тестах, жизненный цикл; правила tsyringe, если он выбран.
- [Database Access](Database-Access.md) — шаблон: схема, клиент ORM, поток миграций, где ORM разрешён в коде.
- [Test-Setup](Test-Setup.md) — шаблон: раннер, герметичность прогона, виды интеграционных тестов, фейки.
- [Deployment](Deployment.md) — шаблон: пайплайн, секреты, ресурсы production, восстановление базы, проверки после деплоя.
- [Platform](Platform.md) — профиль платформы: рантайм, время жизни контейнера, лимиты и транзакции БД, очереди, расписания, тестовый рантайм, деплой. Соглашения ниже от платформы не зависят; как они исполняются на ней — здесь.

### Conventions (соглашения)

- [Layer Boundaries](Conventions/Layer-Boundaries.md) — что в каком слое лежит и чего там быть не должно; какие паттерны DDD сознательно не используются.
- [Naming](Conventions/Naming.md) — именование файлов и типов.
- [Signatures](Conventions/Signatures.md) — сигнатуры методов репозиториев и сервисов.
- [Testing](Conventions/Testing.md) — где лежат тесты, герметичность, фейки вместо контейнера.
- [Errors](Conventions/Errors.md) — формат ошибок API и кто за что отвечает.
- [Background Jobs](Conventions/Background-Jobs.md) — сообщения очередей, идемпотентность, повторы, расписания, что проверять в тестах.
- [Database](Conventions/Database.md) — схема под нагрузку: индексы, агрегаты, курсорная пагинация, транзакции, миграции, которые удаляют или переносят данные.

### [ADR](../../../docs/ADR/README.md)

Architecture Decision Records — значимые архитектурные и продуктовые решения и их
причины. Лежат в корневой `docs/ADR/`: они относятся ко всем приложениям.
